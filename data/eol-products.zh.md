# EOL 产品清单（中文站）

本文件是 <https://www.inhand.com.cn/support/eol-products> 页面表格的唯一数据源。
**中英文两站内容本来就不一样，各自维护各自的文件，互不影响。** 英文站见
[eol-products.en.md](eol-products.en.md)。

## 怎么改

**最省事的办法：不要改这个文件，去提一个变更申请。**
在仓库的 Issues 页点 New issue → 选「EOL 产品变更申请」，填一个表单（操作类型、
型号、日期），提交后机器人会自动改好这张表并开一个 PR，维护人核对合并即可。
全程不用碰 Markdown，也不用装 Git。

下面是直接改文件的方式，适合熟悉 Git 的维护人：

1. 直接编辑下面这张表：新增一行 / 改一行 / 删一行，保持五列不变。
2. 日期写 `YYYY-MM-DD`（也接受官网上那种 `7/24/2026` 的写法，同步时自动转换）。
3. 提 PR。CI 会跑一次预演，在 Checks 里打印这次改动会让官网**新增/更新/删除**哪些记录，
   确认无误再合并。合并到 `master` 后自动同步到官网，不需要再手工改官网上的表格。
4. **删掉这一行，官网上的同款记录也会被删除**（合并后自动同步）。删除是永久、不可恢复的，
   所以删型号前仔细核对；演练时可用 `--no-delete` 或 PR 的预演先看效果。

这张表同时也是文档站 EOL 页面的来源：CI 会由它生成
`docs/zh/EOL Products/EOL Products.md`，随手册站发布并进 `llms.txt`（AI 问答/爬虫可查）。
那个页面是自动生成的，别去手改，改这里。

本地预演：`python scripts/sync_eol_products.py --site zh --dry-run`

## 多人同时改怎么办

表里每一行是一个独立产品，**各改各的行不会互相干扰**，Git 会自动合并。真正会撞车的
只有两种情况：两个人都往**表格末尾追加**新行，或两个人改**同一行**。

少撞车的两个习惯：

- **新增时插到对应系列那一段里**（IR 的加到 IR 那几行中间，ER 的加到 ER 那段），
  别所有人都往最后一行后面加——位置错开就不会撞。
- **改之前先同步最新版**（`git pull`，或在网页上重新打开文件），改完尽快提 PR 合掉，
  别让分支放一周。

**万一提示冲突（conflict），不要慌，新增撞新增是最好处理的一种**：两边都是对的，
把两行都留下就行。文件里会出现这样三行标记：

```
<<<<<<< HEAD
| IR999-XX 系列 | IR315-FF39系列 | 2027-01-01 | 2027-03-01 | 2030-01-01 |
=======
| ER888-YY | ER815-NRQ1 | 2027-02-01 | 2027-04-01 | 2030-02-01 |
>>>>>>> 同事的分支
```

处理办法：**删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记，两条产品行都保留**，保存提交即可。
GitHub 网页上点 “Resolve conflicts” 就能直接编辑，不用命令行。
如果两人改的是同一行、内容对不上，别自己挑一个，先跟对方确认哪个是准的。

合并后 PR 的预演会把最终结果打印出来，合并前再核一眼即可。
