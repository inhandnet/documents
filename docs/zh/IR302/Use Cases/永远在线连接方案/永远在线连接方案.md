# 高可用在线联网方案

**产品：** InHand IR302 工业级蜂窝路由器
**应用场景：** 双链路（WAN / 蜂窝 / Wi-Fi）互联网冗余，保障现场站点持续在线

---

## 1. 方案概述

### 1.1 背景

在工业物联网（Industrial IoT）、智慧零售、无人值守终端、智能售货、交通运输及远程监控等场景中，现场路由器是本地设备（POS、自助机、PLC、摄像头、传感器、边缘控制器）与中心平台之间唯一的通信通道。无论是宽带、蜂窝还是 Wi-Fi，单一上行链路都存在单点故障风险：光缆被挖断、基站中断、运营商维护窗口或蜂窝小区临时不稳定，都足以导致整个站点断网。对于依赖实时数据、支付授权、远程控制或告警上报的业务而言，即使短短几分钟的停机，也会直接造成收入损失和紧急上门维护。

**InHand IR302 工业级蜂窝路由器**通过在单一设备中整合多种上行链路（以太网 WAN、4G/LTE 蜂窝、Wi-Fi STA），并内置**链路备份（Link Backup）**功能来解决这一问题。启用链路备份后，路由器会持续使用 ICMP 探测监控各上行链路的健康状态，一旦主链路故障，立即将默认路由切换至健康的备用链路；主链路恢复后，又会自动切回，无需人工干预。

### 1.2 目标

- 消除单一上行链路中断导致站点停机的风险。
- 实现主备链路之间的自动、亚分钟级故障切换（failover）。
- 主链路恢复后，自动回切至首选链路（通常成本更低、速率更高）。
- 通过冷切换模式控制蜂窝数据消耗：备用链路仅在需要时拨号上线。
- 支持主动/主动模式（负载均衡，Load Balance），满足需要更高吞吐量的站点。
- 首次上电配置后无需现场人员介入，可通过 InHand Device Manager 完全远程管理。

### 1.3 应用场景

IR302 + 链路备份方案适用于任何将互联网可用性视为业务关键的站点：

- **零售/连锁门店** — POS 终端、支付网关、电子价签；宽带为主链路，4G 为备份。
- **自助与无人值守终端** — ATM、票务机、充电桩、自动售货机；蜂窝为主链路，第二 SIM 或 Wi-Fi 为备份。
- **医疗设备** — 联网医疗设备和远程诊断终端，数据交付不能中断。
- **工业现场与智能制造** — PLC / SCADA 上传链路、MES  connectivity。
- **智慧城市与交通** — 信号控制器、视频监控、环境监测。
- **分支机构与远程办公点** — 作为返回总部 VPN 隧道的备份上行链路。
- **移动资产** — 车辆与临时部署站点，使用两个运营商实现全国覆盖。

> **本手册参考示例：** 某站点以**以太网 WAN 为主链路**、**4G 蜂窝为备份链路**，ICMP 探测目标为 `8.8.8.8`，备份模式为**热切换（Hot failover）**。

## 2. 需求分析

### 2.1 现场情况

| 项目 | 典型值 |
|---|---|
| 站点类型 | 零售 / 自助机 / 工业 / 分支办公 / 车载 |
| 本地设备 | POS / PLC / IPC / 摄像头 / 自助机 / 医疗设备 |
| LAN 接口 | RJ45 以太网（`LAN2`） |
| 可用上行链路 | 以太网 WAN、4G/LTE、Wi-Fi STA |
| 电源 | DC 9–36 V（符合 IR302 输入范围） |
| 部署方式 | 室内机柜、室外机箱、车载 |
| 可管理性 | 本地 Web UI + 远程 Device Manager 云平台 |

### 2.2 核心需求

1. **高可用性** — 至少两条独立上行链路；一条故障时，另一条必须自动接管。
2. **探测机制** — 链路健康状态需通过真实互联网目标检测，而非仅依赖本地接口状态。
3. **可预测的切换** — 主链路与备份链路定义清晰，故障切换与回切行为可预期。
4. **带宽/成本控制** — 可选择让蜂窝 SIM 卡仅在有线链路真正中断时才启用。
5. **吞吐量选项** — 部分站点希望将流量在两条链路上负载均衡，而非一直 standby。
6. **远程运维（O&M）** — 通过 InHand Device Manager 实现远程配置、远程诊断和远程固件升级。
7. **安全性** — 加密 Web UI、基于角色的本地访问、可修改默认凭据、配置备份/恢复。

## 3. 整体架构

### 3.1 逻辑架构（四层）

1. **感知层** — 路由器后方的现场设备（POS、PLC、摄像头、医疗设备、自助机）。
2. **网络层** — 支持多上行链路（以太网 WAN、4G/LTE、Wi-Fi STA）并运行链路备份功能的 IR302。
3. **传输层** — 通过当前活动上行链路接入公共互联网；可选 VPN 隧道（OpenVPN / IPsec / L2TP）。
4. **应用/云** — 业务平台、物联网云、支付网关、视频平台或 InHand Device Manager。

### 3.2 方案拓扑

```

   │ Field device │  (POS / PLC / IPC / kiosk / medical)
   └──────┬───────┘
          │ Ethernet (LAN2)

   │   │  Ethernet WAN      │   │  4G / LTE (SIM) ││

                  │ (default route)     │ (standby / hot)
                  ▼                     ▼

                  │                     │
                  └──────────┬──────────┘
                             ▼
                  Cloud platform / HQ / Device Manager
```

### 3.3 数据流（南向 → 北向）

1. 本地设备将流量发送到其默认网关，即 IR302 的 LAN IP。
2. IR302 通过当前活动的默认路由转发流量，正常运行时该路由为主链路。
3. 链路备份引擎通过 ICMP 探测（默认目标 `8.8.8.8`）验证各配置链路的互联网可达性。
4. 若主链路探测失败（链路中断、无载波、运营商故障），路由器将默认路由切换至备份链路。
5. 主链路中断期间，所有生产流量由备份链路承载。
6. 一旦主链路恢复并通过探测，路由器立即将默认路由回切至主链路。
7. 若选择**负载均衡（Load Balance）**模式，路由器则会将出站会话同时分发到两条链路，而非一主一备。

## 4. 网络与连接设计

### 4.1 上行链路选择

| 选项 | 推荐使用场景 |
|---|---|
| 以太网 WAN（宽带/光纤） | 已有有线互联网的固定站点 — **典型主链路** |
| 4G/LTE 蜂窝 | 移动资产、远程站点或固定站点的**典型备份链路** |
| Wi-Fi STA | 拥有可靠上游 Wi-Fi 的站点（如租户 Wi-Fi），可作为主链路或备份链路 |
| 双 SIM（视型号而定） | 需要运营商级冗余的关键任务站点 |

### 4.2 备份模式

IR302 的链路备份功能支持三种模式；根据您的运营优先级选择：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| **热切换（Hot failover）** | 两条链路始终保持在线。主链路故障时，流量立即切换至已经在线的备份链路。备份链路会消耗少量数据以保持连接。 | 对**故障切换速度**要求高于蜂窝数据成本的场景（支付、医疗、告警）。 |
| **冷切换（Cold failover）** | 仅主链路保持连接。备份链路仅在主链路中断时才拨号上线。正常运行期间蜂窝流量为零。 | 希望**最小化 SIM 数据费用**的场景；由于备份链路需要拨号，故障切换会稍慢几秒。 |
| **负载均衡（Load Balance）** | 出站流量同时分摊到两条链路。 | 双 SIM 吞吐量聚合，或需要同时使用两条链路的站点。 |

### 4.3 选择 IR302 的理由

- **多原生上行链路** — 在单台工业级设备中集成 4G/LTE、以太网 WAN、Wi-Fi。
- **内置链路备份** — 无需额外授权或硬件，开箱即支持 WAN + 蜂窝故障切换。
- **基于 ICMP 的健康检查** — 真正的端到端互联网探测，而非仅判断接口 up/down。
- **工业设计** — DC 9–36 V 宽电压、宽温、反接/浪涌保护、看门狗（watchdog）。
- **支持 VPN** — 任一链路均可支持 OpenVPN、IPsec、L2TP、GRE。
- **远程运维** — 通过 InHand Device Manager 云实现大规模设备的远程配置和 OTA 升级。

## 5. 协议与探测机制

### 5.1 南向（LAN 侧）

- 通过以太网（RJ45 `LAN2`）连接本地设备或 LAN 交换机。
- LAN 侧可启用 DHCP 服务器（可选，可配置）。
- 路由器后方的任何 IP 设备均受支持（POS、PLC、IPC、自助机、医疗设备等）。

### 5.2 北向（WAN 侧）

- **以太网 WAN** — `WAN/LAN` 端口配置为 WAN，支持 DHCP / 静态 / PPPoE。
- **蜂窝** — 4G/LTE SIM，支持公网 APN 或专网 APN。
- **Wi-Fi STA** — 将 IR302 作为客户端连接到上游 Wi-Fi 网络。

### 5.3 链路健康探测

IR302 会周期性从每条受监控链路向可配置的目标 IP 发送**ICMP echo 请求**。只要 echo 响应在超时窗口内返回，链路即视为健康。默认目标：`8.8.8.8`（Google 公共 DNS）。该目标可更改为任何长期在线的公网 IP，或客户自有的总部/服务器端点。

## 6. 安全

- **本地 Web UI** — 通过用户名/密码保护（出厂默认 `adm` / `123456`，也可在设备标签上查看 — **首次登录必须修改**）。
- **远程管理** — 默认禁用；如需启用，仅在 WAN 侧开启 HTTPS / SSH。
- **配置备份** — 完整配置可通过 Web UI 导出和导入；建议每次修改后备份。
- **Device Manager** — 安全、集中化的远程管理、审计和 OTA 升级。

## 7. 方案亮点

1. **持续在线** — 在 WAN / 蜂窝 / Wi-Fi 任意两种链路之间实现自动、亚分钟级故障切换。
2. **三种模式，一套硬件** — 热切换求速度、冷切换省成本、负载均衡追吞吐；无需更换硬件，按站点灵活选择。
3. **真实互联网探测** — ICMP 探测公网目标，避免“接口已 up，但互联网不通”的常见问题。
4. **零接触回切** — 主链路恢复后，路由器静默切回；无需现场拜访或人工操作。
5. **工业级品质** — 宽电压、宽温、看门狗、浪涌保护 — 专为无人值守部署设计。
6. **海量设备就绪** — 通过 InHand Device Manager 实现数百乃至数千台 IR302 的远程运维。
