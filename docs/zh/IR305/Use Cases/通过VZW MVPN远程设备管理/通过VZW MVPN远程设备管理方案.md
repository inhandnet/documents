# 通过 VZW MVPN 进行远程设备管理

## 背景

在工业部署中，PLC 等现场设备分布在多个无人值守的远端站点。每个站点通过工业路由器 IR305 接入 Verizon Wireless 的专用网络（MVPN / Private APN），并由运营商分配一个唯一的 VZW 私网 WAN IP。

由于所有路由器采用相同的 LAN 子网（例如 `192.168.2.x`），各站点 PLC 的 IP 地址存在重叠。中心服务器需要远程访问每个站点的 PLC，以完成配置、监控和故障诊断，并通过各路由器唯一的 WAN IP 进行区分。

## 目标

- 实现对全网站点现场 PLC 的远程访问，无需现场人工介入
- 利用各路由器唯一的 VZW WAN IP 穿越 NAT，直接访问 PLC
- 支持远程配置、状态轮询和故障告警
- 降低现场巡检成本，减少对现场人员的依赖

## 应用场景

- 远程 PLC 监控与管理（油气、公用事业、水处理、制造等行业）
- 每个站点部署 1 台 PLC、且无固定宽带的跨站点场景
- 中央 SCADA / HMI 平台通过蜂窝 NAT 访问现场设备
- 通过远程诊断与配置降低现场巡检成本

## 解决方案：DMZ 配置

在每台 IR305 上启用 DMZ（Demilitarized Zone，隔离区），将所有入站 WAN 流量直接转发到 LAN 侧的 PLC。由于每台路由器拥有唯一的 VZW WAN IP，中心服务器只需访问对应站点的 WAN IP，即可到达该站点的 PLC；无需逐端口映射，所有 PLC 协议端口均透明可达。

## 配置参数

| 参数 | 取值 |
|-----------|-------|
| Enable DMZ | Enabled |
| DMZ Host | `192.168.2.2`（PLC IP） |
| Source Address Range | 中心服务器 IP，例如 `192.x.x.x/32` |
| Interface | Cellular |

## 流量走向

```
Central Server → VZW Private Network → IR305 WAN → DMZ → PLC (192.168.2.2)
```

访问 `192.168.11.1` 即可到达站点 1 的 PLC，访问 `192.168.11.2` 即可到达站点 2 的 PLC，以此类推。本方案支持 TCP 流量，但 ICMP（ping）按设计不支持。

## 方案亮点

1. **现场零改动：** 无需调整 PLC 配置，只需在 IR305 上启用 DMZ
2. **部署简单：** 一条规则覆盖所有协议端口，无需逐端口映射
3. **私网安全：** VZW MVPN 使所有流量不经过公共互联网
4. **易于扩展：** 新增站点仅需部署一台 IR305 并启用 DMZ
